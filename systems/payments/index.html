System 02 · Settlement

机器可支付接口

当一个调用方没有账户、没有银行卡、也无法完成实名验证时，它仍然可以为一次推理付费。这是两条为此设计的结算轨道。

两条轨道

Rails

x402 · USDC on Base

基于 HTTP 402 的链上结算。调用方签署一次授权，服务端通过 facilitator 校验并结算。

scheme=exact · network=eip155:8453 · asset=USDC

L402 · Lightning

基于闪电发票的微支付。付款后凭 preimage 换取一个带配额与有效期的令牌。

BOLT11 · HMAC token · quota + TTL

调用流程

Flow
# x402
GET  /x402/quote                  -> 402 + PAYMENT-REQUIRED (requirements + invoice/accepts)
POST /x402/v1/chat/completions    -> PAYMENT-SIGNATURE: <base64 payload>
                                  -> 200 + PAYMENT-RESPONSE (settlement receipt)

# L402
GET  /paid/quote                  -> 402 + { invoice, verify_url, receipt }
GET  /paid/check?receipt=...      -> { settled, token, quota, ttl_sec }
POST /paid/v1/chat/completions    -> Authorization: L402 <token>

为什么是这两条

Rationale

无账户授权
持有支付工具本身就是授权凭据，不需要注册与会话。

原子性
一次付款对应一次调用，额度与有效期写进令牌，服务端无需保存状态。

可审计
链上交易哈希与闪电 preimage 都是可验证的结算凭证。
