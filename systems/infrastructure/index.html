边缘交付与运维

内容必须在任何单一服务失效时依然可达，异常必须在用户察觉之前被记录。这是交付层的两条硬性要求。

三镜像

Tri-mirror
镜像角色说明
Netlify CDN主站file-digest 部署，显式 MIME 与 _headers 双保险
GitHub Pages冷备同一份内容，独立构建与独立域名
Edge runtime动态镜像Workers / Deno：常驻服务与反代入口
原则　三个镜像共享同一份源文件，但部署路径、证书与故障域完全独立。

常驻服务

Edge services

反代入口

通过重写规则把 /gw/* 映射到边缘函数，使网关在不暴露源站的前提下可直连访问。

边缘推理

在 Deno 运行时上运行同一套网关逻辑，作为独立于本机的第三条接入路径。

Watchdog

心跳
服务端口与健康端点，30 分钟一次。

磁盘
剩余空间低于阈值才告警。

证书
到期前按剩余天数分级提醒。

告警只在状态变化时发送，避免重复噪音；历史写入本地日志，便于回溯。
